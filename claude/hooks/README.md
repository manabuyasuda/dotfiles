# hooks の実装規約

`claude/hooks/` と `cursor/hooks/` のスクリプトが守る規約です。フックはツール実行のたびに起動するため、1回あたりの処理が全体の応答速度に直結します。

## 外部コマンドを起動しない

bashの組み込み機能で同じ結果が得られる処理では、外部コマンドを呼びません。

判断の理由は、macOSのセキュリティソフトが常駐監視（Endpoint Security）でプロセスの起動を検証するためです。検証はプロセスが起動するたびに発生し、検証が滞ると監視自体が停止して、その間すべてのアプリの操作が待たされてしまいます。フックは1回のツール実行につき複数が並行して起動し、それぞれが共通ライブラリを読み込むため、1コマンドの削減がそのまま倍数で効きます。

### `$0` の親ディレクトリ

各スクリプトの冒頭で `_HOOK_DIR` を定義し、以降はこれを使います。

```bash
_HOOK_DIR="${0%/*}"
[ "$_HOOK_DIR" = "$0" ] && _HOOK_DIR="."
```

2行目は、`$0` にスラッシュが含まれないとき（カレントディレクトリから実行されたとき）に `${0%/*}` が `$0` をそのまま返すことへの対処です。

`dirname` を使いません。共通ライブラリを読み込むたびに1プロセス増えます。

ファイル編集時に走る4フック（branch-guard・plan-guard・file-protect・mermaid-guard）の実測では、この置き換えで `dirname` の起動が10個から1個になりました。残る1個は `lib/find-bin.sh` がディレクトリを遡る処理で使うもので、`$0` を対象としないため置き換えの対象外です。

### その他の置き換え

| 外部コマンド | bash の組み込み機能 |
|---|---|
| `$(dirname "$path")` | `${path%/*}` |
| `$(basename "$path")` | `${path##*/}` |
| `$(cat file)` | `$(<file)` |
| `$(echo "$s" \| rev \| sed …)` | パラメーター展開と文字列操作 |

`jq`・`grep`・`git` は判定処理そのものに使うため、置き換えの対象外です。
