# x-why-so

文章を命題ごとの行に分け、トゥールミン・モデルの要素として箇条書きに並べます。欠けている情報を埋めてから、書き直し案を示します。採否はユーザーが決めます。

## 要素

| 要素 | 定義 |
|---|---|
| 主張 | 書き手が読み手に受け入れさせたい結論です。 |
| データ | 主張を支えるために示す事実です。読み手が真偽を確かめられる形で書きます。 |
| 論拠 | データから主張を導いてよいとする、一般的な規則です。文章に書かれないことが多くあります。 |
| 裏づけ | 論拠を支えるために示す事実です。データと同じ種類の事実でも、論拠を支えるものは裏づけに当たります。 |
| 限定条件 | 主張がどの程度確かか、どの範囲で成り立つかを示す語です。独立した行にはせず、主張の行の中に残します。 |
| 例外 | 主張が成り立たなくなる条件です。トゥールミン・モデルの「反駁」に当たります。例外に書くのは、主張への反論に答える文ではなく、主張が成り立たなくなる条件だけです。 |

## 手順

### 1. 構造を書き出す

- 1つの述語で言い切れる命題ごとに1行を作ります。名詞を修飾する節は、修飾される名詞と同じ行にまとめます
- 行の先頭に要素名を書き、支える行を、支えられる行の下に字下げして置きます
- 主張を最上位に置きます。見出しがあれば、見出しから主張を決めます
- データは、そのデータを支えるデータを下に持てます
- 文末は常体にし、名詞で終わる文は「である」で終えます。否定文は、肯定文に言い換えられる場合だけ言い換えます
- 指示語と省略された語は、原文の別の文にある語で埋め、埋めた語を「【】」で囲みます。原文のどこにもない語は「＿＿」にします
- 「AのB」のように関係が複数に読める語は、関係を表す語で書き、書き足した語を「【】」で囲みます
- 一文の分割、常体への統一、肯定文への言い換えには「【】」を付けません。これらは原文にある情報の書き表し方を変えるだけで、原文が読み手に渡していない情報を補うものではないからです
- 主張を導くのに欠かせない行が原文にない場合は、推測した文を書き、要素名の後に「（原文になし）」と添えます
- 各行は、その行だけを読んで理解できるようにします

出力の例は次のとおりです。

```markdown
- 主張：おそらく、太郎は日本国民である。
  - データ：【太郎の】父は、太郎が生まれたときに日本国民だった。
  - 論拠（原文になし）：生まれたときに父または母が日本国民である子は、日本国民である。
    - 裏づけ：国籍法第2条が、生まれたときに父または母が日本国民である子を、日本国民と定めている。
  - 例外：太郎が国外で生まれて外国の国籍も得ており、日本の国籍を留保する届を出していない場合は、日本国民ではない。
```

### 2. 欠けを埋める

「＿＿」と「（原文になし）」の行を、1つずつ次の順で扱います。

1. リポジトリのコードと設定、公式ドキュメントで確かめられるものは、エージェントが調べて埋めます
2. 調べて確かめられないものは、x-grillingでユーザーに質問して埋めます
3. 質問しても埋まらないものは、その行を消すか、主張を変えるかをユーザーに決めてもらいます

原文、調査結果、回答にある情報だけで埋めます。すべての欠けを解消してから、次の手順に進みます。

### 3. 確からしさを検討する

主張ごとに、次の5つの基準で支えが足りているかを確かめます。

| 基準 | 確かめること |
|---|---|
| 関連性 | データが、主張の真偽に関係しているか |
| 確かさ | データが、観察や出典で確かめられるか |
| 十分さ | データの量と種類が、主張の強さに見合っているか |
| 論拠 | データから主張を導く論拠が受け入れられ、必要な裏づけがあるか |
| 例外 | 主張が成り立たない条件を検討し、限定条件で主張の範囲を絞っているか |

基準を満たさない箇所は、x-grillingでユーザーと検討します。データを足すか、限定条件で主張を弱めるか、主張を消すかを決めます。すべての主張の確からしさをユーザーが十分と判断したら、次の手順に進みます。主張のない文章（手順や事実の説明など）では、この手順を省きます。

### 4. 構造を保存する

構造を対象のファイルと同じディレクトリに`<対象のファイル名から拡張子を除いた名前>.why-so.md`として保存し、パスをユーザーに伝えます。対象が`docs/plan.md`であれば、保存先は`docs/plan.why-so.md`です。

ファイルの先頭に次の2行を記述して対象外にします。

```markdown
<!-- textlint-disable -->
> 一時的に作成しているファイルです。校正は禁止です。
```

### 5. 書き直し案を示す

手順1で書き出した構造に「【】」「＿＿」「（原文になし）」が1つもなければ、原文だけで構造を復元できたことになります。その旨をユーザーに伝えて、この手順を省きます。

いずれかがあれば、その箇所は原文が読み手に渡していない情報です。原文側で情報を補い、原文の文体のまま本文を書き直します。書き直した本文に手順1を適用し、3つの記法がなくなるまで直します。

書き直し案と、変更点ごとの理由をユーザーに示します。採用するかはユーザーが決めます。原文のファイルはそのまま残します。
