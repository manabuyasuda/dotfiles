---
name: x-argument-map
allowed-tools: Read, Write, Bash, Agent
description: 日本語文書を段落ごとに分析し、主張・根拠・接続・反対の見方を洗い出して、理解しにくい箇所や根拠の薄い主張をユーザーとの対話で書き直します。「何が言いたいのか分からない」「論点を整理して」「主張と根拠を洗い出して」「argument-map」と言われた場合に必ず使います。書き手の意図を推測する用途には使いません。
---

表記・語彙・文の書き方はjapanese-writing-reviewが担当し、本スキルは論の構造だけを扱います。推奨する起動順はjapanese-writing-review → x-argument-mapで、本スキルは全体の文章が定まってから起動します。

## 1. 段落と文の構造を抽出する

実行前提として`uv`が使える環境を用意してください。

`uv run scripts/extract.py <対象ファイル>`を実行します。次の項目がJSONで標準出力に返ります。判定表の作成と変更一覧の提示で参照できるよう手元へ記録します。

| フィールド | 内容 |
|---|---|
| `paragraphs[].first_sentence` | 各段落の最初の文が入ります |
| `sentences[].assertive` | 言い切っているかを真偽で表します |
| `sentences[].hedges` | 留保表現を一覧で返します |
| `sentences[].evidence` | 根拠マーカーを一覧で返します |
| `sentences[].leading_conjunction` | 文頭の接続詞を返します |
| `sentences[].adversative_particle` | 文中の逆接接続助詞（〜が、〜けれど等）を返します |
| `sentences[].has_adversative` | 文頭または文中で逆接を含むかを真偽で表します |
| `sentences[].content_nouns` | 形式名詞を除いた名詞を一覧で返します（段2の話題語比較と段3の問い3で使います） |
| `sentences[].redundant_with_prev` | 同一段落内の直前文と`content_nouns`を比べ、当該文の全語が直前文へ含まれる場合に真を返します（当該文が空の場合は偽）。段3の問い7で使います |

あわせて全体の文字数・文数・留保表現の総数を記録します。

## 2. 段落の最初の文だけで筋が追えるか確認する

`paragraphs[]`のうち`kind == "body"`のものを対象にし、`first_sentence`を段落順に並べて順に読みます。見出しと箇条書き（`kind`が`heading`・`list`）は前段落を受ける接続を持たないため、段落間の筋を追う対象から除きます。

各段落について、前の段落の`first_sentence`と次の段落の`first_sentence`の`content_nouns`（形式名詞を除いた名詞の一覧）を突き合わせ、共通する語が1語以上あるか、`leading_conjunction`で受けているかを確かめます。どちらもなければ「つながりなし」と記録します。

記録は段落番号とあわせて手元に残し、判定表（次の段）を作ったあとに表の直下に併記します。

## 3. 判定表の作成

`paragraphs[]`のうち`kind == "body"`のものを対象にし、段落ごとに次の7つの問いに答え、判定表にまとめます。見出しと箇条書き（`kind`が`heading`・`list`）は主張と根拠の対応を段落単位で持たないため、判定の対象から外します。判断の材料はJSONに限定し、JSONで足りない段落だけ本文を参照します。参照した文は表の「本文参照」に`sentences[].index`の番号で書きます。

| # | 問い | 判断の材料 |
|---|------|-----------|
| 1 | この段落の主張候補はどの文か | `assertive`が真で`hedges`が空の文。最初の文と一致しなければ両方を挙げる |
| 2 | 主張に対応する根拠はどの文か | `evidence`が空でない文 |
| 3 | 根拠は主張と関連しているか | 主張の文の`content_nouns`（形式名詞除外リスト適用後の名詞）のうちどれかを、根拠の文が文字列として含むか |
| 4 | 反対の見方を扱っているか | `has_adversative`が真の文の有無（文頭の逆接接続詞または文中の逆接接続助詞のどちらかが立てば真） |
| 5 | 接続は主張と根拠のならびに合っているか | `causal`の接続詞が根拠より前に出ていないか。`additive`が3文以上続いていないか |
| 6 | 段落から削れる候補の文はあるか | 問い1で主張候補にも問い2で根拠にも選ばれず、`leading_conjunction`が空で接続にも寄与しない文の有無。問い1で主張候補が1件以上、または問い2で根拠が1件以上ある段落だけを対象とします |
| 7 | 前の文と意味が重複する文はあるか | `redundant_with_prev`が真の文の有無。名詞の集合が包含関係にあるかと、文末の表層形が一致するかだけを見ているため、動詞・形容詞・同義語による重複は検出できません |

各問いの回答は次の判定語に対応させます。

- 問い1: 主張候補が最初の文と一致する場合は「一致」、一致しない場合は「不一致」、`assertive`かつ`hedges`が空の文が段落内にない場合は「言い切っていない」とします
- 問い2: 該当する文が段落内にある場合は文番号、他段落にある場合は段落番号、段落内・他段落ともにない場合は「根拠なし」とします
- 問い3: 主張の語を含む場合は「関連あり」、含まない場合は「関連不明」とします。段2で「つながりなし」と記録した段落は自動で「関連不明」とします
- 問い4: `has_adversative`が真の文がある場合は「反対の見方あり」（文番号を付記）、ない場合は「反対の見方なし」とします
- 問い5: ならびに合う場合は「整合」、合わない場合は「不整合」（causalが前・additive過多のどちらかを併記）とします
- 問い6: 該当する文がある場合は「削れる候補あり」（文番号を付記）、ない場合は「削れる候補なし」とします
- 問い7: 該当する文がある場合は「意味重複あり」（文番号を付記）、ない場合は「意味重複なし」とします

判定表を`${TMPDIR:-/tmp}/argument-map-<basename>.md`に、抽出JSONを`${TMPDIR:-/tmp}/argument-map-<basename>.json`に保存します。`${TMPDIR:-/tmp}`はOSの一時ディレクトリです。macOSでは`$TMPDIR`が自動で設定され、それ以外の環境では`/tmp`にフォールバックします。`<basename>`は対象ファイルの拡張子を除いたファイル名です。後の段で参照するため、この段の完了時にWriteで書き出します。

## 4. x-grillingによる質問

判定表で「根拠なし」「不一致」「関連不明」「反対の見方なし」「不整合」「言い切っていない」「削れる候補あり」「意味重複あり」となった段落を対象に、x-grillingを起動して質問します。「一致」「関連あり」「反対の見方あり」「整合」「削れる候補なし」「意味重複なし」は書き直しが不要なため、質問の対象から外します。

質問の順序はx-grillingの「根本的な決定から」ではなく、判定の重い順に固定します。理由は、根拠のない主張が外れると後続の質問が不要になるためです。

1. 根拠なし
2. 不一致
3. 関連不明
4. 反対の見方なし
5. 不整合
6. 言い切っていない
7. 削れる候補あり
8. 意味重複あり

判定は8種すべてを1ラウンドずつ扱いますが、件数が多い判定は複数ラウンドに分けてかまいません。1ラウンド内で該当段落が3を超える場合は、根拠なしの深刻さ（本文から外れる可能性がある）を基準に3件を選び、残りは次のラウンドに送ります。前段の判定でユーザーが「本文から外す」と答えて外れた段落は、後段の対象から自動で外します。

同じ段落内の同じ文が問い6（削れる候補あり）と問い7（意味重複あり）の両方に該当する場合は、問い6の質問だけを出し、問い7はスキップします。同じ文について同じ「本文に残しますか」の判断を2度尋ねるとユーザーの回答負荷が増え、回答が食い違うと段5でどう書き直すかを決められなくなるためです。

質問文はx-grillingの形式（背景→はい／いいえの肯定文、推奨回答つき、1ラウンド最大3問）に従います。各判定に対する質問と推奨回答のテンプレートは次のとおりです。

| 判定 | 質問 | 推奨回答 |
|---|---|---|
| 根拠なし | <段落>の「<主張>」には、文書内に根拠となる文がありません。この主張を本文に残しますか | 本文から外して、末尾の「根拠を要する主張」に移す。根拠を示せない主張は本文から外すのが安全 |
| 不一致 | <段落>は最初の文「<A>」で始まりますが、断定しているのは「<B>」です。この段落の言いたいことは<B>ですか | <B>を段落の主張として先頭に置き直す |
| 関連不明 | <段落>の「<根拠>」は「<主張>」を支える文として書かれていますが、主張の語を含みません。この文を主張の根拠として扱いますか | 別の主張の根拠か、根拠ではない補足として位置づけ直す |
| 反対の見方なし | <段落>の「<主張>」には、反対の見方（「しかし」「ただし」等で始まる文）が段落内にありません。反対の見方を段落に示しますか | 示す。反対の見方を検討していない主張は根拠が弱く見えるため、想定される反論を一文で加える |
| 不整合 | <段落>では<causalが根拠より前／additiveが3文以上連続>となっていて、主張と根拠のならびが合っていません。ならびを直しますか | 直す。causalは根拠の直後に、additiveの連続は主張ごとに区切る |
| 言い切っていない | <段落>の主張は「<留保表現>」で終わり、言い切っていません。この段落は言い切らないままにしますか | 言い切らないままにし、その理由をユーザーが一文で示します |
| 削れる候補あり | <段落>の「<該当文>」は主張にも根拠にも選ばれず、接続にも寄与していません。この文を本文に残しますか | 本文から外す。目的関数（文と文章の量を必要最小限にする）に沿うため |
| 意味重複あり | <段落>の「<該当文>」は、直前の文と含まれる名詞が同じで新しい情報がありません。この文を本文に残しますか | 本文から外す。目的関数（文と文章の量を必要最小限にする）に沿うため |

回答の受け付けはx-grillingに従います（Q番号での個別回答・「全部それで」の一括採用）。

## 5. 完成稿と変更一覧の提示

x-grillingの回答と抽出時のJSONを根拠に書き直します。書き手の意図は推測せず、回答で扱いが決まった文とJSONで抽出できた構造だけを判断材料にします。判定が「一致」「関連あり」「反対の見方あり」「整合」だった段落と、質問対象のうちユーザーが「変えない」と答えた段落は変えません。

判定語ごとの書き直し操作は次のとおりです。

| 判定 | 書き直し操作 |
|---|---|
| 不一致 | ユーザーが選んだ文を段落の先頭に置き直します |
| 根拠なし | ユーザーが「残さない」と答えた主張を本文から外し、末尾に「根拠を要する主張」として一覧にします |
| 関連不明 | ユーザー回答にしたがって、根拠を別の主張の直後に移すか、根拠ではない補足として位置づけ直すか、本文から外します |
| 反対の見方なし | ユーザーが「示す」と答えた場合は、ユーザーが示した反対の見方を主張の直後に一文で追加します。「示さない」と答えた場合は、その理由を段落末に一文で追加します |
| 不整合 | causalの接続詞は根拠の直後に置き、3文以上続くadditiveは主張ごとに区切ります |
| 言い切っていない | ユーザーが「言い切らないままにする」と答えた段落は、末尾にユーザーが示した理由を一文で追加します |
| 削れる候補あり | ユーザーが「残さない」と答えた文を段落から削ります。「残す」と答えた文はそのまま維持します |
| 意味重複あり | ユーザーが「残さない」と答えた文を段落から削ります。「残す」と答えた文はそのまま維持します |

書き直しの過程で判定表になかった書き換え（文の削除・追加・語句の言い換え）が必要になった場合は、追加の質問ラウンドをx-grillingで実行してユーザーに確認します。追加のラウンドは、段4のラウンドとは別の独立したラウンドとして扱います。

完成稿は段1で渡された対象ファイルをWriteで上書きします。差分の把握と巻き戻しはgitで行うため、書き出し先は段1で渡された対象ファイルに限定します。

上書きしたあと、次の内容を含む変更一覧をチャットに出力します。

- 段落ごとの変更点（並べ替え・末尾へ移動・追記・削除・そのまま維持）と、対応するx-grillingの回答を注記します
- 並べ替えで前段落の語を受けていた文が浮く場合は「元の位置: L<n>」を添えます（ユーザーが戻せるようにするため）
- 書き直し前後の数値と差分を並べます。対象はextract.pyから取得する値（文字数・文数・留保表現の総数）と、x-grillingの回答から集計する値（末尾に移した主張の数）です。数値の減少は目的関数（文と文章の量を必要最小限にする）の指標であって、書き直しが良くなったかどうかの判断はユーザーが完成稿の内容を読んで行います
- 「意味重複あり」の判定は、名詞の集合が包含関係にあるかと、文末の表層形が一致するかだけを見ているため、同義語・言い換えによる重複は検出できていない可能性があります。完成稿を読み直して確認してくださいという注意書きを添えます
