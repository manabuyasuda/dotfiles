# grill with goal

次の4つの観点を理解してください。

1. 目的：この仕事が完了したあとに実現したい変化
2. 完了条件：目的が達成されたことを客観的に評価する基準
3. 制約：満たさねばならない条件や制限
4. スコープ外：考えなくてもいいことや、あえて対象に含めないこと

x-grillingを起動してください。まず「いつ、どこで、どのような出来事があって、この仕事をすることにしましたか」と問いかけます。実際に起きた出来事を答えられない場合は、目的を仮説として扱うと記録して先へ進みます。
続けて、4つの観点を、順番に問いかけてください。
その時点で明確な回答が難しい場合は、仮の内容で次に進んでも構いません。後の観点の回答と前の観点の回答が矛盾したら、前の観点へ戻って検討しなおします。
該当がない観点は「なし（確認済み）」と記述して、まだ確認していない状態と区別します。
すべての観点は最終的に確定させてください。

回答は次のルールにしたがって記述します。

| ルール | 適用する観点 |
|---|---|
| 実際に起きた出来事（いつ・どこで・何が起きたか）を根拠に記述します | 目的 |
| 5W1H（Five Ws）を明確にします | 目的 |
| バリュープロポジションキャンバス（Value Proposition Canvas）を明確にします | 目的 |
| 目的が複数ある場合は、優先順位を付けます。優先順位を決められない場合は、「状況AならX、状況BならY」のように条件付きで順位を決めます | 目的 |
| SMARTの法則を満たします | 完了条件 |
| 否定形は使わず、すべてを肯定形にします。肯定形にできない場合は、対象を列挙できる範囲に限定して、項目ごとに肯定形で記述します。限定もできない場合は完了条件から外して、制約に記述します | 完了条件 |
| 決定論的・機械的・定量的な基準を優先しつつ、それが難しい場合に確率論的・定性的な基準を採用します | 完了条件 |
| 制約が1つあれば、それが守られていることを確認できる完了条件も1つ記述します | 制約 |
| 多義的な表現は避けて、誰がいつ読んでも同じ解釈をする表現にします | すべて |
| 議論したが採用しなかったことも記録します | すべて |

回答を受け取るたびに、上記のルールを上から順に確認します。違反があれば書き直さず、ユーザーへ問い返します。

最後に4つの観点を要約して、ユーザーに最終的な合意をとってください。
