# x-japanese-writing-review スキル

`.md` ファイルの日本語文章品質を、ルールに基づきレビュー・修正します。`context: fork` で実行し、Read/Editの往復を親コンテキストに残しません。

起動はユーザーの明示的な依頼だけです。`textlint-edited-files.sh`（Stop hook）はtextlintで機械的に検出できる範囲だけを扱い、このスキルを起動しません。

## ルール

ルールは、違反をどう判定するかで5つのファイルに分けています。ファイルはこのSKILL.mdと同じディレクトリに置いています。

上から順に当てはめ、最初に該当したファイルへ割り当てます。

| 順 | 判定の質問 | ファイル |
|---|---|---|
| 1 | 本文の意味を読まずに、記号・空白・Markdown記法・文体の形だけで違反だとわかるか | `rule-formatting.md` |
| 2 | その記述を削除しても、読み手の判断が変わらないか | `rule-concise.md` |
| 3 | 読み手が同じ文書内の別の箇所を探しに行く必要が生じるか | `rule-self-contained.md` |
| 4 | その文または前後の文が複数の意味に解釈できるか | `rule-unambiguous.md` |
| 5 | 読み手が次の行動や採否を決めるのに必要な情報が欠けているか | `rule-actionable.md` |

## 対象の決定

引数と差分の有無で対象範囲が変わります。差分があればその範囲だけを、差分がなければファイル全体を校正します。引数にディレクトリを渡された場合は、その配下の`.md`ファイルをすべて対象にします。

### 対象外（Git管理外）の判定

引数にかかわらず、次のいずれかに該当するファイルは校正の対象に含めません。コミットされない一時ファイルのため、文章品質をレビューする意味がありません。該当したら周回せず「対象外（Git管理外のため）」として終了します。

- `.gitignore`で除外されているファイル（`git check-ignore -q <path>`が成立するもの）
- エージェントがコミット対象外と認識しているファイル（作業記録ディレクトリ・一時ファイルなど）

### 対象範囲

| 入力 | 対象範囲 |
|------|---------|
| パスのみ（差分あり） | `git diff -- <path>` と `git diff --cached -- <path>` の差分範囲 |
| パスのみ（差分なし） | ファイル全体 |
| 範囲指定あり（行番号など） | 指定範囲のみ |
| `staged` | `git diff --cached --name-only` で対象ファイルを取得し、その差分範囲 |
| 「ファイル全体」を明示 | 差分の有無にかかわらずファイル全体 |

対象ファイルが複数ある場合は、1ファイルずつ3周を完了させてから次のファイルへ移ります。

## 手順

同じ周回を3回繰り返します。1周目で網羅したつもりでも、2周目・3周目には別の違反が見つかるためです。

各周回で次を実施します。

1. 5つのルールファイルに1対1で対応するサブエージェントを、1回のメッセージで同時に起動します。各サブエージェントには、対象ファイルのパスと対象範囲、担当するルールファイルのパスを渡します。指示は次のとおりです。「担当ファイルのルールに違反する箇所と修正案を返してください。ファイルは読み取りだけを行ってください」
2. 5つの指摘を1つに統合します。同じ箇所について複数の指摘が出た場合は、`rule-formatting.md`→`rule-concise.md`→`rule-self-contained.md`→`rule-unambiguous.md`→`rule-actionable.md`の順で先にあるファイルの指摘を採用します。採用する指摘を決められない場合は、同じ箇所に出たすべての指摘をユーザーへ報告して修正を保留します
3. 統合した指摘のうち、対象範囲に含まれる箇所をすべてEditで修正します。直す箇所がなければ「現状で問題なし」として次の周回へ進みます

サブエージェントは指摘と修正案だけを返します。Editを実行するのは、このスキルを実行しているエージェントだけです。5つのサブエージェントが同じファイルを変更すると、後から実行したEditが前の修正を消してしまいます。

ステージング対象ファイルを修正した場合、`git diff -- <path>` を実行します。ステージングにのみ存在する行（`-` 行）が生じている場合はユーザーに報告して修正を中断します。

2周目以降は前の周回の判断を引きずらず、毎回ゼロベースで評価します。3周完了したら修正内容の概要を報告します。

## 注意

- 文体・構造・表現の修正のみを行います。技術的な内容（コマンド本体・関数名・ファイル名・設定値・JSON構造など）は変更しません
- コードブロック内に書かれた日本語のコメント（`# ...` / `// ...` / `/* ... */` など）は、本文と同じ基準でルール対象とします。コードブロック外と内でルール適用基準を変えません
- コード本体（識別子・キーワード・文字列リテラル・SQL/jq式の中身など）はレビュー対象外です
- ルール違反がなくtextlintの残エラーもない場合は変更しません
- ルールに当てはまるかを判定できない箇所は修正せず、該当箇所と修正案をユーザーへ報告します。判定に迷う箇所を書き換えると、ユーザーが意図して書いた表現を失ってしまいます
- Editは違反箇所のテキストのみを置換します。違反を含む段落・セクション・ファイル全体をnew_stringに置き換えるような広範なEditは行いません

## やらないこと

- 英語など日本語以外の文章のレビュー（対象は日本語の `.md`）
- 技術的内容の書き換え（コマンド・関数名・設定値・JSON構造など）
- `git add` / `git commit` などのステージング・コミット操作
