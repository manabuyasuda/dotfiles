# x-japanese-writing-review スキル

`.md` ファイルの日本語文章品質を、ルールに基づきレビュー・修正します。

## ルール

ルールが目指すのは、読み手が最初から最後まで1度読めば内容を理解でき、何をすべきか・何をしてはいけないかを判断できる文章です。

ルールは、違反をどう判定するかで5つのファイルに分けています。ファイルはこのSKILL.mdと同じディレクトリに置いています。

上から順に当てはめ、最初に該当したファイルへ割り当てます。

| 順 | 判定の質問 | ファイル |
|---|---|---|
| 1 | 本文の意味を読まずに、記号・空白・Markdown記法・文体の形だけで違反だとわかるか | `rule-formatting.md` |
| 2 | その記述を削除しても、読み手の判断が変わらないか | `rule-concise.md` |
| 3 | 読み手が同じ文書内の別の箇所を探しに行く必要が生じるか | `rule-self-contained.md` |
| 4 | その文または前後の文が複数の意味に解釈できるか | `rule-unambiguous.md` |
| 5 | 読み手が次の行動や採否を決めるのに必要な情報が欠けているか | `rule-actionable.md` |

## 対象の決定

引数で渡されたファイルの全体を校正します。引数にディレクトリを渡された場合は、その配下の`.md`ファイルをすべて対象にします。行番号や見出しで範囲を指定された場合だけ、その範囲に限定します。

### Git管理外のファイルを対象外にする判定

引数にかかわらず、次のいずれかに該当するファイルは校正の対象に含めません。コミットされない一時ファイルのため、文章品質をレビューする意味がありません。該当したら周回せず「Git管理外のため対象外」として終了します。

- `.gitignore`で除外されているファイル（`git check-ignore -q <path>`が成立するもの）
- 作業記録ディレクトリや一時ファイルのように、エージェントがコミット対象外と認識しているファイル

対象ファイルが複数ある場合は、1ファイルずつ3周を完了させてから次のファイルへ移ります。

## 手順

同じ周回を3回繰り返します。1周目で網羅したつもりでも、2周目・3周目には別の違反が見つかるためです。

各周回で次を実施します。

1. 5つのルールファイルに1対1で対応するサブエージェントを、1回のメッセージで同時に起動します。各サブエージェントには、対象ファイルのパスと対象範囲、担当するルールファイルのパスを渡します。指示は次のとおりです。「担当ファイルと、担当ファイルが読むよう指定しているファイルを読んでから、担当ファイルのルールに違反する箇所と修正案を返してください。ファイルは読み取りだけを行ってください」
2. 5つの指摘を1つに統合します。同じ箇所について複数の指摘が出た場合は、`rule-formatting.md`→`rule-concise.md`→`rule-self-contained.md`→`rule-unambiguous.md`→`rule-actionable.md`の順で先にあるファイルの指摘を採用します。採用する指摘を決められない場合は、同じ箇所に出たすべての指摘をユーザーへ報告して修正を保留します
3. 統合した指摘のうち、対象範囲に含まれる箇所をすべてEditで修正します。ただし、元の文書にない情報（数値・条件・文と文の関係など）が必要な指摘はEditせず、会話やリポジトリからもっとも確からしい候補を挙げてユーザーへ示します。候補を挙げられない場合は、その情報を調べる方法を提案します。直す箇所がなければ「現状で問題なし」として次の周回へ進みます
4. Editする前に、`methods/check-information-loss.md`の手順で、削除や書き換えによって、読み手の得られる情報が減らないかを確かめます。情報が減る場合は修正しません

サブエージェントは指摘と修正案だけを返します。Editを実行するのは、このスキルを実行しているエージェントだけです。5つのサブエージェントが同じファイルを変更すると、後から実行したEditが前の修正を消してしまいます。

2周目以降は前の周回の判断を引きずらず、毎回ゼロベースで評価します。3周完了したら修正内容の概要を報告します。

## 注意

- 文体・構造・表現の修正のみを行います。コマンド本体・関数名・ファイル名・設定値・JSON構造などの技術的な内容は変更しません
- コードブロック内に`# ...`・`// ...`・`/* ... */`で書かれた日本語のコメントは、本文と同じ基準でルール対象とします。コードブロック外と内でルール適用基準を変えません
- ルールに当てはまるかを判定できない箇所は修正せず、該当箇所と修正案をユーザーへ報告します。判定に迷う箇所を書き換えると、ユーザーが意図して書いた表現を失ってしまいます
- 書き換えるのは違反している語句だけです。違反を含む段落・セクション・ファイル全体を書き直しません
- `git add`・`git commit`・`git stash`・`git restore`のような、ステージングやコミットの状態を変える操作は行いません。実行するGitコマンドは`git check-ignore`だけです
