# check-information-loss.mdのテストの入力

各項目は「比べる見出しや文」と「削除の候補の文」の組です。`check-information-loss.md`の手順で、候補の文を削除するかどうかを判定してください。

1. 比べる文：「ファイルを3件更新しました。」
   候補の文：「指示どおりに進めたためです。」
2. 比べる文：「このスクリプトは、エラーの原因を探すためにログを検索します。」
   候補の文：「エラーが起きたときは、このスクリプトでログを検索してください。」
3. 比べる文：「このhookは、保護ブランチへのコミットを拒否します。」
   候補の文：「つまり、保護ブランチには直接コミットできません。」
4. 比べる文：「ルールが情報を足すことを求める例は変更しません。」
   候補の文：「これらは正だけに情報が増えることがルールの内容だからです。」
5. 比べる見出し：「## 用語の統一」
   候補の文：「用語の統一について説明します。」
6. 比べる文：「タイムアウトは60秒です。」
   候補の文：「60秒を過ぎると、リクエストは失敗として扱われます。」
7. 比べる文：「ログは日付ごとのファイルに分けて保存します。」
   候補の文：「1日分のログを1つのファイルにまとめるためです。」
8. 比べる見出し：「## キャッシュの削除」
   候補の文：「デプロイの前に、キャッシュを削除してください。」
9. 比べる見出し（コミットメッセージの件名）：「エラーメッセージに、原因ごとの対処を1つずつ書く」
   候補の文（本文）：「エラーメッセージの文面を書き換え、原因ごとに対処を1つ書くようにしました。」
10. 比べる文：「テストを3件追加しました。」
   候補の文：「追加したテストは、いずれも境界値を検証します。」

番号ごとに「削除するか（はい/いいえ）」と、判定の理由を1文で書いてください。

## 書き換えの判定

各項目は、書き換える前と後の文の組です。文書にはこの1文しかないものとして、`check-information-loss.md`の手順で、書き換えてよいかを判定してください。

11. 書き換える前：「検索結果は、拠点ごとの組にして表示します。」
    書き換えた後：「検索結果は、拠点ごとに分けて表示します。」
12. 書き換える前：「60秒を過ぎると、リクエストは失敗として扱われます。」
    書き換えた後：「60秒を過ぎると、リクエストは失敗します。」
13. 書き換える前：「このスクリプトは、利用者がエラーの原因を探すことを助けます。」
    書き換えた後：「このスクリプトは、ログを検索します。」
14. 書き換える前：「設定値を、起動時に1回だけ読み込みます。」
    書き換えた後：「設定値を、起動時に一度だけ読み込みます。」

番号ごとに「書き換えてよいか（はい/いいえ）」と、判定の理由を1文で書いてください。
