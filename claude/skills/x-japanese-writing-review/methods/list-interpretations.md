# 語句や文が、複数の意味に解釈できるかを判定する手順

成り立つ解釈を挙げてから、前後の文で絞り込みます。手順の結果だけで判定します。

## 手順

1. 判定する語句と、その語句を含む文を書き出します
2. 判定する語句について、成り立つ解釈をすべて挙げます。挙げるのは、語の辞書的な意味と文法から成り立つ解釈だけです。解釈は、次の観点のうち当てはまるものから挙げます
   - 語の意味：その語が辞書で持つ意味のうち、文に当てはまるもの
   - かかり先：修飾する語や助詞が、どの語にかかるか
   - 文と文の関係：連用形やて形、接続表現で結んだ前後が、並列・因果・時間順・条件のどれか。関係を調べるときは、同じディレクトリの`split-into-elements.md`の手順で述語どうしの関係を書き出します
   - 基準：「最新」「来週」のような語が、いつ・何を基準にしているか
   - 指す範囲：「対応する」「処理する」のように、具体的な操作を複数含む語は、含む操作をそれぞれ解釈として挙げます
3. 挙げた解釈を1つずつ、その文と前後の文に照らします。その文や前後の文と矛盾する解釈は除き、除いた根拠にした語を書きます。たとえば「部署ごとの組に分けます」の「組」は「2人ずつの組」とも読めますが、「部署ごとの」と矛盾するので除きます
4. 残った解釈どうしで、読み手が取る行動か、読み手が理解する事実が変わるかを確かめます。変わる解釈が2つ以上残った場合は、違反と判定します。解釈が1つも残らない場合も、語の意味が前後の文と合っていないので、違反と判定します。残った解釈が1つの場合と、解釈によって行動も事実も変わらない場合は、違反と判定しません
5. 違反と判定した場合、書き手の意図を文書から1つに決められるときだけ修正案を示します。解釈が1つも残らなかった場合は、前後の文に書かれた内容に合う語を修正案にします。決められないときは、元の文書にない情報が必要だとして、残った解釈を候補として示します。ただし、残った解釈のすべてに当てはまる、文字どおりの意味の語があるときは、その語に置き換える案を修正案にします。どの解釈かは決まらないままなので、残った解釈も候補として示します。たとえば「ログを日付ごとの組にして保存します」は、日付ごとに別のファイルにする解釈と、1つのファイルの中で日付ごとに区切る解釈が残ります。「ログを日付ごとに分けて保存します」はどちらの解釈とも矛盾しないので、修正案にします
