# 日本語表現ルール

日本語の表現・語彙の使い方に関するルールです。このファイル内の例示はルール定義のための禁止表現サンプルなので、該当するtextlintルールはファイル先頭で無効化しています。

## 差分で検出できるルール

- 英数字・記号と日本語の間は詰めて書く。バッククォートで囲まれたインラインコードの前後も詰めて書く
  - 正：「Claude Codeを使う」「`true`の場合」「`config.json`を読み込む」「`true`です」
  - 誤：「Claude Codeを使う」「`true` の場合」「`config.json` を読み込む」「`true` です」
- 冗長な表現は短く書く（「することができます」→「できます」、「最初に」→「まず」、「する必要があります」→「してください」）
- 文は述語（動詞・形容詞・助動詞）で終える（名詞で文を終えると時制（する／した）や意図（する／できる／したい）が曖昧になるため）
- 漢語の複合名詞を動詞句で表現する。「未〜」「〜外」「〜値」のような漢語複合名詞は、動詞句に置き換えて自然な日本語にする（「未取得」→「取得できていない」、「定義外」→「対応していない」、「未知値」→「対応していない値」）
- 1つの文では1つの事柄だけを述べる（1文に複数の事柄を入れると、どれが主張なのかを読み手が判断できなくなってしまうため）
  - 正：「hookは保護ブランチへの書き込みを拒否します。拒否されたときはフィーチャーブランチを作成してください」
  - 誤：「hookは保護ブランチへの書き込みを拒否するので、拒否されたときはフィーチャーブランチを作成し、そのうえで作業してください」
- 主語を省略せず明示し、主語と述語を対応させる（主語がないと読み手は主体を推測することになり、主語と述語がねじれると文の意味を取り違えてしまうため）
  - 正：「このスキルは差分だけを校正します」
  - 誤：「このスキルの目的は、差分だけを校正します」
- 修飾部分が長い文は、文の趣旨を先に述べて文を閉じ、修飾部分を後続の文で補足する
  - 正：「校正の対象は差分だけです。ファイル全体を対象にするのは、ユーザーが明示したときに限ります」
  - 誤：「校正の対象は、ユーザーがファイル全体を対象にすると明示したときを除いて差分だけです」
- 地の文を言い切ってから、引用部分を独立した文として書く（地の文に引用を埋め込むと、どこまでが引用なのかが読み手に伝わらないため）
  - 正：「ユーザーは次のように述べました。「差分だけを対象にしてください」」
  - 誤：「ユーザーが差分だけを対象にしてくださいと述べたため、対象を限定します」
- 修飾語は被修飾語の直前に置き、複数の修飾語が並ぶときは長い修飾語を先に、短い修飾語を後に置く（修飾語と被修飾語が離れると、どの語にかかるのかが定まらなくなってしまうため）
  - 正：「昨日エラーが発生した本番環境のログ」
  - 誤：「本番環境の昨日エラーが発生したログ」
- 「てにをは」は3点を確認する。既知の主題には「は」を、新しく導入する主語には「が」を使う。同一の文で同じ助詞を重ねない。「の」を3つ以上連続させない
  - 正：「エラーが発生したときは、hookが処理を止めます」「設定ファイルを読み込む順序」
  - 誤：「エラーは発生したときは、hookは処理を止めます」「設定ファイルの読み込みの処理の順序」

## 段落の読み込みが必要なルール

- 名詞を別の名詞にかけるときは、助詞（の・による・に関する等）または活用形（した・する・な等）を補って修飾関係を明示する（名詞を直接つなげた複合名詞は係り受けが曖昧になるため）
- 「場合」と「とき」を使い分ける。条件・仮定的な状況には「場合」を使い、時間的な局面・瞬間には「とき」を使う（「残高が不足している場合は」「エラーが発生したときは」）
- テスト名など技術的な文脈では、技術的な語（`null`・`true`・`false`・数値コード等）をドメイン語で表現し、技術語は括弧内に補足する（「nullを返す」ではなく「ラベルを表示しない（null）」）
- 説明文には振る舞いだけを書く（「当日の日付を固定するため」「フラグがセットされているため」等の実装の内部事情は削除する。理由を知りたい読み手は実装を読むため）
- 動詞は文字どおりの意味で使う。「施策に効く」のように薬の作用に例えず、何がどう良くなるのかを書く。「テストを回す」のように物を動かす動作に例えず、実際に何を実行するのかを書く。「表現を借りる」のように物のやり取りに例えず、どこの何をどう使うのかを書く。「コードを育てる」のように生き物の成長に例えず、何をどう変えていくのかを書く
- 実害を述べる文は、否定的評価を表す表現で望ましくない結果であることを明示する。確実に起きることは「〜てしまう」、起こりうることは「〜かねない」「〜おそれがある」、結果を引き起こすことは「〜を招く」「〜を損なう」を使う。中立な事実の記述には使わない
  - 正：「把握しないまま決めると、自分の成果物を説明できなくなってしまう」
  - 誤：「把握しないまま決めると、自分の成果物を説明できなくなる」
- 効果や利点を述べる文は、何がどれだけ変わるかを書く。数えられるものは定量的に書く。数えられないものは変化の前後がわかるように書く。「改善する」「保たれる」「期待できる」のような評価の語だけで済ませない（具体的な変化がないと読み手は取り入れるかを判断できず、効果があったかも確かめられないため）
  - 正：「1周あたりのRead回数が10回から3回に減る」
  - 誤：「レビューの効率が改善する」
- 変更した前後の差分は、変更前と変更後を対にして書く
  - 正：「モデルIDを`claude-fable-5`から`claude-fable-5-1`へ変更する」
  - 誤：「モデルIDを修正する」
- 説明を付け足すときは、付け足す前の文から同じことが言えるなら書かない。指示に従ったことを示すだけの説明も書かない
  - 正：「変更前と変更後を対にして書く。読み手が変更前の値を探して元の版を開かずに済むためである」
  - 誤：「変更前と変更後を対にして書く。読み手が差分を把握しやすくなるためである」
  - 誤：「ファイルを3件更新した。指示どおりに進めたためである」
- 接続表現は、前後の文の論理関係に対応する種類のものを選ぶ（論理関係と異なる種類の接続表現を使うと、読み手が文のつながりを取り違えてしまうため）。種類は7つある
  - 付加：論理が同じ方向に進むときに使う（例：「そして」「また」「さらに」「しかも」「むしろ」）
  - 理由：理由を示すときに使う（例：「なぜなら」「というのは」）
  - 例示：例を挙げるときに使う（例：「たとえば」「例を挙げると」）
  - 転換：論理が逆の方向に進むときに使う（例：「しかし」「だが」「けれども」）
  - 解説：言い換えるときに使う。前後の文はイコールの関係になる（例：「すなわち」「つまり」「というのは」）
  - 帰結：まとめや結論を述べるときに使う（例：「要するに」「したがって」「だから」「つまり」）
  - 補足：付け足すときに使う（例：「なお」「ただし」）
  - 正：「差分だけを対象にします。なぜなら、変更していない箇所まで直すとレビュー範囲が広がってしまうためです」（後の文が理由を述べているので理由の接続表現を使う）
  - 誤：「差分だけを対象にします。また、変更していない箇所まで直すとレビュー範囲が広がってしまうためです」（後の文が理由を述べているのに付加の接続表現を使っている）
