# 文書の構造を、読み手が理解する順序と区切りにするルール

違反を直す主な手段が、段落・文・箇条書きの項目の順序や区切りを変えることかどうかで判定します。

次の表のルールに当てはまるかは、表のメソッドを読み、その手順で判定します。表にないルールは、記号や語の形で判定します。

| ルール | 使うメソッド |
|---|---|
| 1つの段落では、1つの主題だけを扱います | `methods/split-into-elements.md` |
| 段落は、次の順序に従って並べます | `methods/split-into-elements.md` |
| 段落の先頭にトピック文を書きます | `methods/split-into-elements.md` |
| 手順・並列の事柄・構成要素を述べる段落は、箇条書きにします | `methods/split-into-elements.md` |
| 箇条書きの番号は、順序がある場合・項目数を伝える場合・後で番号を参照する場合だけ付けます | `methods/list-interpretations.md` |
| 箇条書きの階層は、項目の先頭に置ける接続表現で決めます | `methods/split-into-elements.md` |
| 文では主文を先に書き、対比・否定・留保はそのあとに書きます | `methods/split-into-elements.md` |

## 1つの段落では、1つの主題だけを扱います

段落の区切りと主題の区切りが一致していないと、読み手はいま何について述べているのかを理解できなくなってしまいます。読み手は見出しから、そのセクションに何が書かれているかを予測できなくなってしまいます。

段落は、1つの主題について書いた文のまとまりで、1つのトピック文と、1つ以上のサポート文で構成します。トピック文には、その段落で書き手が最も伝えたい考えや情報を書きます。サポート文には、トピック文の詳細・理由・具体例を書きます。

主題が変わったら段落を分けます。段落の間は1行空けます。各段落のトピック文だけを並べたときに、要約として筋が通るかを確かめます。通らない場合は、段落の分け方かトピック文を直します。

## 段落は、次の順序に従って並べます

段落の並びが内容の流れと合っていないと、読み手は段落どうしの関係を把握できないまま読み進めてしまいます。

並べ替えるときは、段落の中の文を変えず、段落の順序だけを変えます。並べ替えで、指示語や接続表現の指す先が変わる場合は、その語も直します。

セクションの内容に当てはまる順序に従います。当てはまる順序どうしが矛盾する場合は、番号の小さい順序を優先します。

1. 全体から部分へ
2. 概要から詳細へ
3. 読み手が知っている事柄から、知らない事柄へ
4. 重要な事柄から、補足的な事柄へ
5. 読み手が知りたい事柄から
6. 作業や手順を実行する順に
7. 画面や図の配置に合わせて、左から右へ、上から下へ

## 段落の先頭にトピック文を書きます

トピック文が後ろにあると、読み手は何についての説明かを特定できないまま、理由や経緯を読み進めてしまいます。

先頭に移したトピック文に、主題を示す語句が欠ける場合は補います。

- 誤：「ログを調べたところ、14時にメモリ使用量が上限に達していました。その直後にプロセスが停止していました。原因はメモリ不足だと考えられます」
- 正：「プロセスが停止した原因は、メモリ不足だと考えられます。ログを調べたところ、14時にメモリ使用量が上限に達していました。その直後にプロセスが停止していました」

## 地の文を言い切ってから、引用や例示を独立した段落として書きます

地の文（引用や例示ではない、書き手自身の文）に引用や例示を埋め込むと、どこからどこまでが引用や例示なのかが読み手に伝わらなくなってしまいます。

地の文を句点で閉じ、引用は引用記法で、例示は箇条書きで、別の段落に書きます。

- 誤：「ユーザーが差分だけを対象にしてください、ただしファイル全体を対象にすると明示したときはその範囲を校正してくださいと述べたため、対象を限定します」
- 正：地の文を句点で閉じ、引用を別の段落に置きます。

  ユーザーは次のように述べました。

  > 差分だけを対象にしてください。ただし、ファイル全体を対象にすると明示したときは、その範囲を校正してください。

  そのため、対象を限定します。

## 手順・並列の事柄・構成要素を述べる段落は、箇条書きにします

段落の文の中に項目が並んでいると、読み手は項目の区切りと数を数え直すことになってしまいます。

対象は、次の事柄を1つの段落に並べて書いている箇所です。項目の数では判定しません。

- 順序を持つ物事や、順番に実行する手順
- 並列の事柄
- あるものを構成する項目

誤

```markdown
パッケージをインストールしてから設定ファイルを作成し、そのあとサービスを起動します。
```

正

```markdown
1. パッケージをインストールします
2. 設定ファイルを作成します
3. サービスを起動します
```

## 箇条書きの番号は、順序がある場合・項目数を伝える場合・後で番号を参照する場合だけ付けます

番号が付いていると、読み手は項目に順序があると受け取ってしまいます。

3つのどれにも当てはまらない箇条書きは、番号を外します。

誤

```markdown
対応しているOSは次のとおりです。

1. macOS
2. Linux
3. Windows
```

正

```markdown
対応しているOSは次のとおりです。

- macOS
- Linux
- Windows
```

## 箇条書きの階層は、項目の先頭に置ける接続表現で決めます

階層と項目どうしの関係が合っていないと、読み手は項目どうしの関係を取り違えてしまいます。

直前の項目との間に当てはまる接続表現を考え、その種類で階層を決めます。接続表現は階層を決めるために当てはめるもので、項目に書く必要はありません。

- 直前の項目と同じ階層
  - 付加（「さらに」）
  - 転換（「一方」「しかし」）
  - 帰結（「そのため」「結果として」）
- 直前の項目より1段下の階層
  - 例示（「たとえば」）
  - 解説（「つまり」「すなわち」）
  - 理由（「なぜなら」「というのも」）
- 直前の項目より1段上の階層
  - 総括（「このように」）
  - 直前の項目との関係では接続表現が決まらない別の話題

誤

```markdown
- 境界値のテストを追加します
- 0件と1件の場合を確認します
- 上限の100件の場合を確認します
- 境界値のテストで、入力値の範囲を網羅できます
```

正

```markdown
- 境界値のテストを追加します
  - 0件と1件の場合を確認します
  - 上限の100件の場合を確認します
- 境界値のテストで、入力値の範囲を網羅できます
```

正の2項目目は、1項目目の例示なので1段下げます。3項目目は、2項目目に付加する内容なので、同じ階層に置きます。4項目目は、1〜3項目目の総括なので1段上げます。

## 文では主文を先に書き、対比・否定・留保はそのあとに書きます

対比・否定・留保が先にあると、読み手は何について述べた文かを特定できないまま読み進めてしまいます。

主文は、修飾や対比を取り除いても成り立つ文です。対比・否定・留保を文の先頭に書いてよいのは、打ち消す対象が同じセクション内のその文より前にすでに出ている場合だけです。

- 誤：「校正の対象はファイル全体ではなく、差分です」
- 正：「校正の対象は差分です。ファイル全体は対象にしません」
- 誤：「もちろん、ユーザーが明示したときはファイル全体を対象にします。ただし、原則は差分です」
- 正：「校正の対象は原則として差分です。ユーザーが明示したときだけファイル全体を対象にします」
