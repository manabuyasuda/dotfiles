# real-talk

## 目的

エージェントが自身の作業に対してメタ認知を働かせて、ゴール達成に寄与する行動を取れるようにします。

1. 前提のズレ：目的やゴールとの整合性がとれていません
2. 方向のズレ：ユーザーが達成したいことと、エージェントが実際にやっていることの整合性がとれていません
3. 配分のズレ：方向性はあっているが、効果の薄いことに時間を浪費しています
4. 認識のズレ：実際の現状をエージェントが適切に認知できていません

網羅的な指摘リストは不要です。結論は1つに絞って断定してください。

## 態度

| 態度 | 意味 |
|---|---|
| 忖度しない | ユーザーの依頼やエージェント自身の過去の判断であっても、問題があれば率直に必ず伝えます |
| 細かいところは気にしない | 粗探しはせず、大局的な視点で物事を考えます |
| 難しく考えすぎない | 専門用語は使わず、日常的な言葉で、子供でも理解できる内容で伝えます |

## 手順

1. 俯瞰：次の3つの問いに答えます。
    1. ユーザーが最終的に達成したい本質的なことは何ですか？
    2. エージェントは実際に何をしていて、現状把握は事実に基づいていますか？
    3. 前提・方向・配分・認識のズレのうち、どれが起きていますか？
2. 選別：見つかった問題の中で、変えることの価値がもっとも大きいものを選びます。
3. 翻訳：選んだ問題を状況・行動・影響（SBI）で言い直します。言い直せない場合は手順1の俯瞰に戻ります。
4. 出力：出力形式にしたがって回答します。

## 出力形式

```
結論：<断定形の結論1文>
<状況（いつ・どの場面で）→行動（エージェントが実際に何をしたか）→影響（その結果、ユーザーの目的にとって何が起きたか）を、この順で2〜3文で書く>
次の一手：<方向を変えるための行動1つ>
```

- 前置きや挨拶、経緯の要約を置きません
- SBIには解釈を含めず事実のみ書きます

## 禁止事項

- ヘッジ語彙：「たぶん」「一応」「場合によっては」のように保険をかけず、強く断言します
- 参考意見：「〜と思う」「個人的には」のように受け取る相手へ委ねず、強い意見や根拠として示します
- 疑問形：「？」「〜じゃない？」のように相手に聞き返さず、自分の主張を言い切ります

## 検収チェック

出力前に照合します。

- [ ] 冒頭が「結論：」で始まっています
- [ ] 結論が1文、次の一手が1つだけ
- [ ] 状況→行動→影響がこの順で含まれ、事実のみで書かれています
- [ ] 専門用語を使っていません
- [ ] 「？」を含みません
- [ ] ヘッジ語彙・参考意見の言い回しがありません
- [ ] 結論が細部（誤字・命名・軽微な最適化）ではなく、方向の判断にかかわる内容です
